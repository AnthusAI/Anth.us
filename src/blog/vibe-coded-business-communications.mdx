_Build presentation decks with AI coding agents armed with Marp._

Slide decks remain a staple deliverable across industries, yet building them manually burns time you could spend on content quality. Marp converts Markdown directly into HTML, PDF, or PowerPoint, so an AI coding agent can generate, lint, and export the deck while you concentrate on sharpening the message.<Citation

* **AI coding agent**: Any automation-capable agent (OpenAI GPTs, Cursor, CrewAI, etc.) that can read repositories, invoke commands, and submit pull requests.
* **Single source of truth**: Markdown summaries, metrics, or transcripts stored in Git so the agent can reuse them in the deck.

## Step-by-step workflow

### 1. Outline slides in Markdown

Create a `deck.marp.md` file with a simple template. Ask the agent to bootstrap it from an existing recap, notebook, or doc string.

```markdown
---
theme: gaia
paginate: true
---
# Executive Summary
- Key outcome 1
- Key outcome 2
---
# System Diagram
<!-- Agent inserts architecture callouts here -->
```

### 2. Let the agent populate each section

Provide the agent with the outline, source material (metrics, transcripts, Jira summaries), and instructions such as “keep each slide under five bullets” or “add speaker notes below `---`. Because directives stay inline, the agent can tweak layout properties without leaving Markdown.

### 3. Export deliverables automatically

Teach the agent a single command that produces all required formats:

```bash
npx @marp-team/marp deck.marp.md --html --pdf --pptx --output dist/
```

The agent can watch for changes to data files or meeting notes, rerun the export, and post artifacts to Slack, email, or a shared drive.

### 4. Keep humans in the loop

Use comments or issues to request reviews on specific slides. Because the entire deck is text, diffing becomes trivial and stakeholders can approve changes the same way they approve code.

## Automate refresh cycles

Configure the AI agent with a “prepare deck” action tied to your reporting cadence:

1. Pull the latest Markdown summaries into a `marp/` directory.
2. Insert updated KPIs, diagrams, or quotes.
3. Run the Marp CLI and attach artifacts to the weekly update issue.
4. Notify reviewers with a link to the commit so they can track changes across reporting periods.

This turns presentations into continuously updated documentation rather than one-off files that drift out of sync with the underlying system.

## Tips for crisp AI-assisted decks

* Keep each slide scoped to one insight; ask the agent to split dense sections automatically.
* Provide concrete prompts (“turn quarterly pipeline metrics into a two-column comparison slide”) so the agent knows how to reshape data.
* Use Marp directives like `backgroundImage` or `_class` sparingly—agents handle them well when documented inline.
* Archive every generated deck artifact with the commit hash that produced it to preserve traceability for audits.

By combining Marp’s text-first workflow with AI coding agents, you eliminate the drudgery of presentation building and make it easy to communicate complex ideas on demand.
